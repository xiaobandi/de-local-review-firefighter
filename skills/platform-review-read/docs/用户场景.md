# 用户场景

按「谁 → 什么情况下 → 说什么 → 得到什么 → 注意什么」组织。每个场景都能照着跑一遍。

---

> ⚠️ 本技能尚未填写真实场景（`scenarios`），下面为**通用推导**，信息量有限。

## 场景一 · 使用者的日常用法

- **角色**：使用者
- **触发时机**：需要「平台评价读取」这件事有结果的时候
- **他会说**：`用 platform-review-read 帮我读取评价`
- **需要准备**：平台名称；评价数据（导出或连接器输出）
- **拿到什么**：统一评价流表 + 覆盖度说明
- **容易踩的坑**：无连接器时绝不能凭印象编造评价，只能处理用户提供的文件

---

## 场景二 · 换成你自己的材料

同一句话，把材料换成你手头的真实数据即可：

```text
用 platform-review-read 处理下面这份材料：
<粘贴你的内容 / 贴文件路径>
```

**输入结构不要改**：字段名变了，脚本会读不到；缺字段时应当被明确告知缺什么，而不是猜。

| 字段 | 必填 | 说明 |
|---|---|---|
| 平台名称 | ✅ | 缺失会导致输出不可用 |
| 评价数据（导出或连接器输出） | ✅ | 缺失会导致输出不可用 |
| 时间范围 | ⬜ | 有则更好 |
| 门店/账号 | ⬜ | 有则更好 |
